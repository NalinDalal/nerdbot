**Audit basis:** HEAD `6d325a7`, source inspection of `backend/src/nerdbot/{api.py,models.py,store.py,orchestrator.py,executor.py,runtime.py,chat.py,app_tools.py,agent_tools.py,approval_flow.py,permissions.py,gates.py,providers.py,workspace.py,library.py,research.py,...}`, `dashboard/src/**`, tests in `tests/**` and `dashboard/src/**/*.test.ts`, and isolated browser smoke/screenshots (labeled fixtures).  
**Status legend:** **Implemented & verified** = code + executed evidence in this audit/prior recorded runs; **Implemented but unverified (this audit)** = implemented with tests/code evidence but not exercised end-to-end in this browser audit; **Partial** = capability exists but incomplete, disconnected, or not coherently surfaced; **Stub/limited** = placeholder/thin behavior; **Absent** = no implementation evidence found.

> Note: endpoint/model presence alone is not treated as proof of a complete user journey. “Frontend entry point” indicates primary reachable UI (may be buried).

## Execution lifecycle (condensed, reconciled)
1. **User assigns/creates work** (UI/API/chat/tool): task stored with project/owner/dependencies/context.  
2. **Run scheduled** (`/tasks/{id}/runs` or async, retry, executor sweep claim+run): orchestrator validates task/owner/provider/command-model viability, creates run, marks running.  
3. **Agent/model selection**: teammate/provider/fallback resolved server-side (`providers.py`, orchestrator).  
4. **Permissions/tools**: tool schemas filtered and gated (`permissions.py`, `gates.py`, `app_tools.py`, `agent_tools.py`); sensitive actions may require approval (`approval_flow.py`).  
5. **Execution**: workspace prepared (`workspace.py`), runtime/agent loop executes with bounds/guardrails/cancellation (`runtime.py`, orchestrator).  
6. **Progress/events**: persisted + streamed (`run_events`, `/runs/{id}/events*`).  
7. **Approval/recovery**: gated actions pause/await decision; decision can resume exact action; sweeps/recovery paths exist but are trigger-dependent (`approval_flow.recover`, executor sweep).  
8. **Persisted outcome**: run/task/artifacts/reviews/PR packages/files/reports/library/gallery records stored; surfaced unevenly in UI.

**Disconnected/manual/conditional:** executor and schedule/reminder/delivery heartbeats require sweeps/cron/opt-in loops; live LLM execution requires reachable provider config; some UI surfaces do not expose all backend outcomes end-to-end.
